# Mill 0.11.0

Preparation reviews can now share one persistent, external session. It reserves
calls before execution, tracks total rounds, measured local tokens and elapsed
time, and supplies earlier findings to each complete exact-candidate reviewer.
Operator-declared hosted requests are counted separately; their usage remains
unavailable.

Repeated P0/P1 in a reported subsystem or exhaustion of normal rounds directs
the supervisor to one preauthorized replan. Recovery uses the remaining original
budget. Acceptance changes require a separately accounted exact-candidate
review. This improves the maintainer preparation route; admitted task repair
limits and push, merge and release approval boundaries remain unchanged.

The packaged helper, negative session tests and legacy receipt regressions cover
accounting, scope, recovery, unavailable usage and unsafe evidence paths.
Existing readiness-first GitHub review behavior is unchanged. The source record
precedes publication; provider qualification and channel readbacks belong to
release assets. Historical longitudinal evidence and its unchanged expiring
support tuple are retained, without renewing a live-worker or broader-stack
claim.
