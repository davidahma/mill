# Bounded preparation review and recovery

This public copy generalizes downstream project identifiers.

David approved this native maintainer increment on 2026-09-29, including Mill's
0.11.0 release and the downstream project's deliberate upgrade. It addresses
repeated preparation reviews while preserving the admitted lifecycle and remote
approval boundaries.

## Scope

Add an optional external preparation session to the packaged maintainer review
route. Its fixed policy binds repository, initial base, allowed paths, total
rounds, recovery rounds, elapsed time, model tokens and hosted requests. Reserve
before validation/model execution; preserve failed attempts and unavailable
usage. Serialize writers and retain receipts. Feed earlier findings and recorded
replans to the complete exact-candidate reviewer as evidence, never
instructions.

After two blocking rounds in the same reported subsystem, or exhaustion of the
normal rounds, direct the supervisor to one preauthorized design reassessment.
The supervisor records a bounded replan and resumes with the remaining total
budget. Changing acceptance requires a separate clean exact-candidate review
before recording the replan. This local evidence does not admit a replacement
runtime task or authorize push, merge, publication or customer activity.

## Acceptance

- Legacy receipt run/check behavior remains available without a session.
- Session policy and cumulative history survive candidate changes; every attempt
  counts, failed/unmeasured calls cannot silently reset the token allowance.
- Malformed policy, symlinks, concurrent writers, changed scope, exhausted
  limits and incomplete attempts fail before another model call.
- Repeated P0/P1 routes to recovery; P2/P3 remains advisory. Recovery consumes
  reserved rounds within the original total and cannot be repeatedly renewed.
- A replan carries the exact candidate, consolidated blockers, design and check
  rationale, permitted paths and independently reviewed acceptance if changed.
- Prior findings/dispositions reach the reviewer without narrowing the diff.
- Hosted requests are operator-declared counts; their tokens remain unavailable.
- Packed installation includes the helper. Documentation describes actual limits
  and the existing readiness-first hosted review flow.

## Validation and delivery

Use focused maintainer/session tests, the complete native gate, source audit and
an independent read-only exact-candidate review before push. Merge through
strict required checks, then qualify the tagged artifact through the existing
release workflow. Update install examples before tagging. Pin the downstream
project only after registry and GitHub readback, with deliberate upgrade checks
and no closed-record rewrites.

No event-sourcing rewrite, new model adapter, repair-budget expansion, automated
merge override, daemon, customer deployment or the downstream project product
implementation.
